Appearance

A look is how the desk is drawn: its sky or its paper, what moves on it, and the colours it brings. Looks are grouped by genre — the weather, paper, a coach's board — and every look has a light and a dark side: the toggle beside the picker switches between them, and Auto follows the system's appearance. The palette a look is drawn on is written to the same ~/.agentdata/config.json that ad-theme set writes, so this project's terminal prompt and tab follow it. A look under Plain is a palette on its own: the plain page in that colour.

The tiers are the widths at which a pane on the desk changes what it draws: a rail, then compact, then full. They start at the numbers CI measures against; set the laptop's here once you have tried them on the real monitors, and every open desk redraws at once (docs/desk-window.md §The tiers).

Model per agent

What each agent is launched with, pressed rather than typed. On CLI default, no --model flag is passed at all and the Copilot CLI picks for itself — which is the only no-model behaviour anyone has measured, so it is the one this uses. A change takes effect on the agent's next turn: the command line is fixed when the process starts.

Copilot

How the fleet launches the Copilot CLI, and how long it waits. Each row says when a change takes effect. Pick one agent to give it values of its own: each of its rows says whether the value is this agent's, every agent's or the default, and use every agent's puts one back. Every value here becomes a flag on that agent's own command line at every launch, its console included — never a write to Copilot's own ~/.copilot/config.json, which your own Copilot chats share.

Copilot's own settings

What the installed Copilot CLI documents for its own /config (copilot help config). A row with a fleet setting beside it is set per agent from this page; the others live in ~/.copilot/config.json, shared with your own chats, and the fleet never writes that file — change them with /config in a Copilot window.

What an agent may run

By default an agent has what a Copilot CLI window has: every tool it would ask about is allowed (--allow-all-tools), and only the fleet's own commands are denied. Set tool access to strict above, for every agent or one, to use the enumerated list below instead.

The base allow-list is read-only here, deliberately. It is the boundary and configuration replaces it rather than adding to it, so a list saved from this page would become the whole boundary — and you would silently stop receiving any command a later version adds. Change it in ~/.agentdata/config.json or through ad-setup. What you can do here is add to it: also allowed (for example powershell for every PowerShell command, or shell(Get-ChildItem) for one) and also denied, for every agent or, with an agent picked above, for that one alone. They are on every launch, so a permission set here does not wear off. The deny-list is a floor: a denial always wins, and an agent never loses one the fleet set.
