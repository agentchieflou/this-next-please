# Code Graph

The code graph subsystem provides static analysis, symbol indexing, repository mapping, and guarded optimizations.

## Layout under `.agent/graph/`

| File | Purpose |
|---|---|
| `graph.json` | Complete deterministic graph: all nodes and edges sorted by id/keys. |
| `meta.json` | Graph metadata: root relpath, file count, extractor counts, the extractor used per file, sha256 hash, and file fingerprints. |
| `understanding.md` | Human-readable explanation generated by `ad-graph explain` / `codebase-map`. |
| `approval.json` | Human approval stamp produced by `ad-graph approve`. |
| `approved-nodes.json` | `{node id: source sha}` at the moment of approval — what `ad-graph status` diffs against to count drift, and what the guard will refuse changes against. |
| `coverage.json` | Test coverage data mapped per node produced by coverage collection. |

## Node Kinds

- **`file`**: Source files (e.g. `agentdata/cli_graph.py`).
- **`class`**: Defined classes (e.g. `agentdata/graph/model.py::Graph`).
- **`function`**: Functions or class methods (e.g. `agentdata/graph/builder.py::build_graph` or `agentdata/graph/model.py::Graph.add_node`).
- **`test`**: Test functions or test methods (e.g. `tests/test_graph.py::test_build_graph`).

Each node carries:
- `id`: Canonical identifier.
- `where`: Line range `path:start-end`.
- `sha`: SHA-256 hash of the node's source slice.
- `loc`: Lines of code.
- `complexity`: Cyclomatic branch complexity.
- `tags`: Special classifications such as `entrypoint` or `io`.

## Edge Kinds

- **`defines`**: File defines class/function, class defines method.
- **`contains`**: Class contains method.
- **`imports`**: File/module imports another module (`ext:<name>` or in-repo file path).
- **`calls`**: Function calls function/method (statically resolved or `unresolved:<name>`).
- **`tests`**: Test node tests symbol (derived from name heuristic or coverage contexts).

## Commands and Questions

| Question an agent asks | Command that answers it |
|---|---|
| Where does execution start, what is the repo layout, what are the hubs? | `ad-graph summary` |
| What does this symbol do, where is it defined, what calls it, what does it call? | `ad-graph node <target>` |
| What breaks if I touch this (blast radius of callers)? | `ad-graph refs <target>` |
| What does this symbol depend on (transitive callees)? | `ad-graph refs <target> --reverse` |
| How does an entrypoint reach an I/O operation or target? | `ad-graph path <from> <to>` |
| Are there circular import or call dependencies? | `ad-graph cycles` |
| What nodes changed on disk or since a git commit? | `ad-graph changed [--since <ref>]` |
| How can a human visualize the code graph in Graphviz? | `ad-graph export --format dot --out .agent/graph/export.dot` |
| Write down what this repo does, in a form a human can review | `ad-graph explain` |
| Has a human approved that understanding, and does it still match the code? | `ad-graph status` |

## The approval gate: why the command needs a terminal

Nothing downstream of the graph — findings, guarded edits, performance work — may run until a human has
read `.agent/graph/understanding.md` and approved it. The `codebase-map` skill writes that document and
stops; a human then runs `ad-graph approve` themselves.

The gate is the command, not the instruction. A line in a SKILL.md saying "do not approve your own work"
is a second line of defence that a model can talk itself past; `ad-graph approve` cannot be talked past
because it refuses to run at all unless **both** `stdin` and `stdout` are a TTY:

- Luna runs its commands with no stdin (`session-bootstrap` step 1). Under a pipe, a redirect, or
  `subprocess` with `stdin=DEVNULL`, `ad-graph approve` exits **3**, prints a `hint`, and writes nothing.
- There is deliberately **no** `--yes` and **no** `--non-interactive` flag. Adding one would hand every
  agent the key to the gate, so the absence of the flag is itself part of the contract and a test asserts
  the argparse namespace never grows one.
- On `y`, the command writes `.agent/graph/approval.json` (`graph_sha256`, `understanding_sha256`,
  `approved_at`, `approved_by` from `git config user.name`) and stamps `state.tools.graph_approved` with
  the short graph sha through the same writer as `ad-state set --tool`. On `n` it writes nothing.

Approval is pinned to two hashes, so it expires by itself. Edit the code and rebuild, or edit the
understanding document, and `ad-graph status` reports `approved: stale` with the number of changed nodes
— the human approved a specific reading of a specific tree, not the repository forever.

## Commands Reference

- `ad-graph build [<root>] [--out .agent/graph] [--force]`: Extracts deterministic graph into `.agent/graph/`.
- `ad-graph summary [--top N]`: Bounded TOON summary of directories, entrypoints, top hubs (fan-in/fan-out), cycles, IO nodes, and test statistics.
- `ad-graph node <target>`: Inspects line location, tags, complexity, LOC, callers, callees, and test linkage.
- `ad-graph refs <target> [--depth N] [--reverse]`: Transitive blast radius up to specified depth.
- `ad-graph path <from> <to> [--all] [--max N]`: Shortest call/import route between two nodes.
- `ad-graph cycles`: Discovers import and call cycles sorted by length.
- `ad-graph changed [--since <ref>]`: Lists modified nodes based on file fingerprints or git diff.
- `ad-graph export --format dot|json --out <file>`: Exports graph to Graphviz DOT or JSON under `.agent/graph/`.
- `ad-graph explain [--out .agent/graph/understanding.md]`: Writes the understanding skeleton from graph facts only — seven sections, every fact line ending in the node id that `ad-graph node` resolves. Re-running preserves anything written between `<!-- model -->` and `<!-- /model -->` and refreshes the facts around it.
- `ad-graph approve`: Human-only. Refuses with exit 3 unless stdin and stdout are both a TTY; see "The approval gate" above.
- `ad-graph status`: Reports `approved: none | current | stale`, both sides of each sha256, and the changed-node count when the approval has gone stale.
