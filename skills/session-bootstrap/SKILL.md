# Session bootstrap

1. Read `AGENTS.md` at repo root and `.agent/state.json`. Either missing → run exactly `ad-setup --only project --non-interactive --offline --project . --set project.jira_project=<KEY>` (`<KEY>`: the Jira project key the user named, else ask; add `--set project.confluence_space=<SPACE>` when known). `--set` answers prompts inline, which is simpler than writing a file and then telling `ad-setup` where it is -- not an encoding workaround. Then continue.
2. Run `ad-doctor --quiet` ONLY if `state.tools.doctor_verified` is not today's date. Command not found → tell the user to run `python -m agentdata doctor --quiet` (same command, always works), and to install or refresh the laptop-wide CLI with `ad-update` (first time: `pip install "agentdata @ git+https://github.com/agentchieflou/this-next-please.git"`). Never run `pip install` inside the project repo: it holds reports, not Python. STOP. `ok: false` → print every `fail` row as `<step>/<check>: <hint>` verbatim, tell the user to run `ad-setup --patch` (it re-asks only the settings behind those rows), STOP. Warnings do not stop you.
3. `ad-state set --tool doctor_verified=<today YYYY-MM-DD>` (skill `state-update`; it is the only way state.json is written).
4. If `state.active_ticket` is set: run `ad-pncli jira search --jql "key = <ticket>"`. Print one line: `<ticket> · <status> · phase=<phase> · branch=<branch>`. If `.agent/desktop.json` exists and is fresh: read it and print: `desktop: <file> · <server>`.
5. If `state.phase == "blocked"`: when an open question names `ad-graph approve`, run `ad-graph status` and print its row — the unblock is a command the human runs, not a sentence they retype. Otherwise read the newest file in `.agent/friction/`, print its `## What would unblock me` section, ask the user for that input. Either way: STOP.
6. Invoke `router`, handing it the `phase`, `active_ticket` and `open_questions` you already read in step 1 — it does not need to open `.agent/state.json` again. Safe because nothing between steps 1 and 6 writes those three keys: step 3 writes only `tools.doctor_verified`. If you ever add a write that touches them, drop this hand-off and let the router read the file.
